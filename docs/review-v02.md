独立审查覆盖 `b9a9ece..c07cfbf` 的清单解析、继承、模板、地址映射、预检和安全测试，提出两项需修复的问题：

| 问题 | 影响 | 状态 |

| SegmentList 的空媒体地址可能回指 MPD | 把 XML 清单当作媒体资源预检成功 | 失败测试复现后修复，复审确认已处理 |
| 模板占位符与原始地址的字面文本碰撞 | 改变资源路径或签名查询 | 失败测试复现后修复，复审确认已处理 |

审查确认了 XML/资源数量限制、固定来源映射、Range 处理、命名空间及动态刷新测试的实现；没有执行真实 PotPlayer 解码。

集成检查还复现并修复了候选按相同 URL 跨 frame 合并的问题：稍后的 iframe 请求不再替换顶层分轨候选的 frame 和请求头。新增回归测试先失败（frame 7 覆盖 frame 0），修复后完整扩展套件 48/48 通过。

## 整体审查

完整 v0.2 分支经过独立整体审查及一次修复差异复审。DASH 专项审查及两轮修复复审也已完成。整体审查的已知重要发现及结果如下：

| 问题 | 修复和证据 |
| --- | --- |
| 同 BV 不同分 P 的 CID、未知初始数据可能错配 | 请求和响应对照路由、视频与分 P 身份；有效 videoData 结构和单视频 CID 仍可识别；往返分 P 不再恢复未知数据的初始豁免 |
| 后到的完整音轨、音频地址或备用地址被去重丢弃 | 两层转发按有界结构化轨道信息去重，保留有效更新，重复扫描不重复发送 |
| 带字面 `$` 的 MPD 根地址仍被当作模板 | 区分已解析地址与清单内模板，完整重写、预检及真实本地资源请求均有回归覆盖 |
| 停止后待处理播放仍可能创建会话 | 取消预检并与创建/启动互斥；8 个并发预检不阻塞停止；迟到回复清理会话 |
| 替换成功后清理旧会话误停新会话 | 旧会话的取消关系仅适用于尚未发布的替换；已建立新会话的双轨请求仍为 200，旧会话清理不影响它 |

上述问题均以失败测试复现后修复，最终构建、59 项扩展测试及完整 Go 并发检查通过。修复差异复审指出的最后两处（返回初始分 P 的豁免、旧会话清理）由作者完成最小修复并自审，**没有把这两处表述为又一次独立复审通过**。

既有播放在来源标签页导航/关闭后继续运行；未完成的发送取消，显式停止统一清理双轨。这项兼容性取舍已在 README 和协议写明。用户需显式结束中转，不能依赖关闭来源标签页停止已经建立的播放。

实际音画、拖动、直播、DASH 和无刷新导航的用户确认见 [验收记录](acceptance.md)。

Node 测试工具现有 `stripTypeScriptTypes` 实验提示已记录；没有以屏蔽警告的方式宣称输出完全无提示。

## 实际验收反馈：CDN 567

用户脱敏报告显示双轨预检成功后，实际音轨请求被 CDN 以 567 拒绝。对照播放器与预检的范围请求差异，并参考 [上游同 CDN 的问题记录](https://github.com/yt-dlp/yt-dlp/issues/17847)，新增了“预检成功、无 Range 播放请求失败”的回归用例，观察失败后修复。

兼容逻辑仅作用于 B 站点播中转；播放器明确指定的 Range/If-Range 保留。不完整的上游 206 不会被冒充为完整 200；普通媒体和直播请求也有不受影响的覆盖。专项并发测试、完整 Go 并发检查、生产构建及 59 项扩展测试通过；这不是新的真实播放通过记录。

## B 站无刷新导航跟进

用户反馈切换网页后没有新来源。自动化复现了预取播放响应被丢弃，以及新元数据和播放响应先后到达、初始状态仍滞后的情况。现只观察网站已请求的公开视频元数据，按当前视频和分 P 的 CID 核对播放信息后转发；缓存限制为 8 份元数据、16 份播放响应、每响应 20 个候选，遵守有效地址期限，禁用时清空并隔离旧请求。

独立审查另复现了旧缺音轨缓存覆盖较新完整双轨的问题。作者新增适配器至候选存储的失败测试后修复：同一内容和匹配画质的完整双轨不被缺音轨更新覆盖；完整地址更新仍生效，其他分 P 不能继承旧音轨。生产构建与完整 73 项测试通过。最终小修复由作者核对，尚无独立复审完成报告；不将其表述为独立复审通过。用户随后按“重载扩展、刷新起始页一次、再无刷新切换”的步骤实测，确认当前来源、内容和音画正常。
