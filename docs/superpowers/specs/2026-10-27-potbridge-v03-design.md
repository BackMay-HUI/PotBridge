# PotBridge v0.3：五主题外观设计

日期：2026-10-27。范围：外观设计、交互原型、正式接入规范。设计提案等待用户视觉确认；没有将设计稿当作已经发布的 v0.3 插件。

## 1. 为什么做

用户希望 v0.3 加入三到五个可切换主题，改善现有界面的质感。最优先的是有明确樱小路露娜立绘的主题；其余参考 Apple、Persona 3 Reload、WinUI 3，其他风格由设计者决定。

此前用户曾指出独立使用时界面过小。当前正式弹窗已经为 560 × 600 CSS px，因此这次保留可读尺寸，重点改变排版层级、字体、色彩、材质和细节。

用户本轮明确选择：

1. 角色立绘在侧边或标题区，保留清晰操作区域。
2. 统一操作布局，各主题具有独立视觉设计。

以下名称、第五主题、默认主题和技术方案是设计者的建议，并非用户逐项指定。

## 2. 方案比较与选定方向

| 方案 | 得失 | 结论 |
| --- | --- | --- |
| 统一操作布局，主题分别定义字体、材质、配色和装饰构图 | 切换后的操作位置稳定，能保留 v0.2 的工作流；仍可形成明确风格差异 | 用户已选择 |
| 每个主题独立布局，尽可能还原参考对象 | 风格变化更强，但五套布局增加学习与维护成本，也会让按钮位置跳动 | 用户未选择 |

不采用仅替换强调色的换肤方式。五主题共享信息顺序与关键控件位置，但边角、阴影、排版、装饰与状态样式都有各自规则。

## 3. 五个主题

| ID / 名称 | 主要视觉 | 字体与形态 | 适合的场景 |
| --- | --- | --- | --- |
| `luna` / 月下礼仪 | 暖象牙白、银灰、墨黑、少量酒红；露娜胸像置于标题区右侧 | 中文宋体式标题、衬线英文标识、细分隔、低圆角卡片；立绘下方柔和收束 | 主推主题，角色陪伴感与清晰操作并存 |
| `porcelain` / 瓷白 | 干净的浅灰白、蓝色操作、轻量层次 | 清楚的无衬线标题、较大圆角、克制阴影；抽象播放图形 | 简洁、通透的 Apple 风格偏好 |
| `reload` / 深蓝时刻 | 深海军蓝、电光蓝、青色操作 | 凝练斜体、切角、强对角线、几何圆环与编号感 | P3R 风格偏好；保留动势但不倾斜正文 |
| `mica` / 云母 | 冷灰、淡蓝紫、浅色高不透明面板 | Segoe UI Variable、本机式控件、细描边和局部亚克力菜单 | 希望和 Windows 桌面协调的用户 |
| `forest` / 墨绿 | 深墨绿、低饱和浅绿、温润浅色文字 | 中文衬线标题、等宽技术数字、平静的线性细节 | 夜间和低刺激观看 |

建议新安装默认 `luna`，尊重最优先的角色主题。已经选择主题的用户，升级后保留选择。当前 v0.2 没有主题设置；是否为 v0.2 升级用户默认使用露娜，可在视觉确认时调整。

## 4. 页面结构

### 4.1 扩展弹窗

桌面基准 560 × 600 CSS px，不通过整体缩放伪造更大分辨率。

从上到下：

1. 品牌、真实本机连接状态、主题切换、设置入口。
2. 当前页面标题与站点信息；角色或几何装饰只在标题区，始终不挡文字。
3. 站点检测开关，开启与关闭有文字状态。
4. 媒体单选列表：画质、格式、编码、音轨完整状态。签名 URL 不进入可见界面。
5. 检测、检查、发送、错误等状态与恢复说明。
6. 固定的主操作“用 PotPlayer 播放”，以及现有辅助操作。
7. 本地处理提示，必要时提供结束中转操作。

中段只有一个滚动区，固定操作区不覆盖内容，长列表和长错误可以滚动到。低高度或放大文字时优先保留操作可达性。实际来自网页的标题保持文本渲染，长标题支持换行，并可通过标题说明读取完整内容；不能让角色图挤出核心内容。

### 4.2 设置页

桌面设置页采用窄侧栏与内容区，最大内容宽度 1040 px；小视口侧栏变为顶部的分组入口。

- 外观与主题：五张主题缩略卡片，选择即应用并自动保存，无需点击连接设置的保存按钮。
- 播放器连接：本机状态、重新检查、播放器路径。首次安装与扩展 ID 可展开，尚未连接时默认展开。
- 网络与诊断：保留系统 / 直连 / 手动代理、手动地址、ffprobe 选项、导出脱敏诊断、结束全部中转。
- 连接配置的“保存设置”仍沿用 v0.2 的显式保存方式；不能将主题改变误当作连接配置提交。

角色图在设置页也仅占标题区域。主题选择必须保持表单内容、滚动位置、当前单选来源和焦点，不通过重建整个页面来换主题。

## 5. 主题交互

弹窗标题栏提供调色板按钮，展开非模态主题选择面板。使用原生单选语义，支持点击、Tab 和方向键选择；Escape 关闭并回到触发按钮。点击面板外侧关闭。不能只靠悬浮提示发现入口。

设置页的主题卡片和弹窗面板使用相同主题 ID。选中状态同时有边框、勾选与文字提示，不能只靠颜色区分。切换立即生效，连接设置无需重新保存。

减少动态效果时关闭位移、旋转和过渡，不使用粒子、背景视频或常驻角色动画。标准模式只保留 160–200ms 的轻量交互反馈；检查进度保留明确文字，不只显示转圈。

## 6. 正式实现的边界和接入方式

正式代码仍沿用现有 TypeScript + 原生 DOM + Vite，不引入 React、UI 框架或运行时动画依赖。主题由根元素 `data-theme`、统一语义 CSS 变量和少量主题装饰规则完成。

建议改动：

- 新增 `extension/src/ui/theme.ts`，管理主题枚举、启动读取、保存、跨页面同步和状态通知。
- `styles.css` 拆出共享组件规则与五组主题 token，消除 v0.2 的重复尺寸覆盖和硬编码绿色状态。
- popup/options HTML 加入同样的主题入口与装饰插槽；保留现有功能 DOM ID 或同步调整对应绑定。
- 立绘作为扩展本地 WebP 资源，不访问 CDN、不增加远程脚本、字体或图片权限。
- 不改动媒体捕获、音轨配对、网络中转、播放器启动和 Native Messaging 协议 2；本轮设计不要求重装本机组件。

### 存储与启动

主题偏好使用 `chrome.storage.local` 的独立键，例如 `appearance: { version: 1, theme: 'luna' }`。通过 `chrome.storage.onChanged` 同步已打开的扩展页面。不要修改现有 enabledOrigins、HostConfig 或使用其保存流程。

为了减少打开弹窗时闪烁，使用扩展本地的早期初始化脚本，在首帧前读取同源 `localStorage` 的主题镜像，再以 `chrome.storage.local` 的真实值校正。两者值只允许固定枚举；损坏、未知主题、读写失败均回退到可用主题，不影响检测和播放。localStorage 仅作为镜像，不能成为另一份永久冲突的来源。

该双层启动方案是设计者提出的实现方向；正式实现时需要验证扩展上下文的 CSP、读取失败和同步顺序。独立设计预览仅用 localStorage 存偏好，不声称已经完成扩展存储接入。

### 网页材质限制

`mica` 通过局部渐变、较高不透明度面板、细描边和菜单 backdrop blur 模拟 Fluent 材质。浏览器扩展无法像 WinUI 原生窗口那样取样真实桌面壁纸；没有伪造系统权限或宣称原生 Mica。常规内容面板保持足够实，保证文本对比度。

### 品牌与资源

保留 PotBridge / 映桥品牌。Apple 和 P3R 用作视觉参考，不复制官方标识、系统窗口按钮或游戏 UI 截图。露娜主题使用基于官方人物辨识参考生成的同人立绘，页面与文档注明出处，不冒充官方美术。

图像原图、WebP 与完整提示词保存在设计目录。正式包只需包含优化后的 WebP，目标资源预算不超过 400 KB；当前 WebP 为 318,606 字节。其余四主题用 CSS / SVG 装饰，不为每款主题加入壁纸。

## 7. 状态语义与功能保留

必须保留 v0.2 的现有语义，视觉主题不能改变可用性判断：

- 无候选、站点关闭、未连接、检查中、所选独立视频缺少音轨时，播放不可用，并给出原因与下一步。
- 检查中按钮提供忙碌状态并防重复提交；不让主题动画延迟请求。
- “已发送”和“播放器已请求媒体”不能写成“播放成功”，实际音画仍由播放器决定。
- “重新获取地址”只在支持的来源上启用，不能因界面美化而对所有来源放开。
- 已开始的播放中转不受主题改变、弹窗关闭或设置页切换影响。
- 结束中转仍明确终止对应会话；结束全部中转是独立操作。
- MP4 / HLS / Bilibili 分轨 / DASH / HTTP-FLV，以及原有诊断和安装错误提示都必须保留。

## 8. 设计验收与正式版本验收分开

本次交付是可操作的设计提案：

- `docs/design/v0.3/index.html`：五主题设计室。
- `screen.html`：共用布局的弹窗和设置页，可以单独打开。
- `theme-data.js` / `themes.css`：主题命名、颜色和组件表达。
- `assets/`：角色立绘、WebP 与提示词。
- `docs/design/v0.3/README.md`：启动方式、参考链接与预览边界。

设计阶段需要实际浏览器检查五种主题、两类页面、主题切换和重新打开、原生键盘操作、六种状态、窄视口、可见焦点和基础文字对比度。检查证据单独记录，不能把示例“已连接”算作 Native Messaging 验收。

正式接入之后才能声称 v0.3 可用；那时仍需生产构建、已有回归测试、主题存储错误 / 同步 / 启动验证，以及 Edge 扩展环境下的切换、播放、设置不丢失的实际检查。只有设计获准后进入正式实现与发布流程。

## 9. 参考与筛选

使用用户指定、本地安装的 ui-ux-pro-max 技能查询设计体系、玻璃材质与键盘焦点。

首次 `desktop media utility elegant themes --design-system` 返回营销网站布局和不适合中文工具界面的字号 / 字体搭配，未采用也未保存为规范。按技能要求收窄为 `productivity desktop settings minimal`，获得 Minimalism & Swiss Style，采用其功能层级、留白、单主操作和低成本反馈原则；不照搬营销 CTA 位置或自动推荐的红绿配色。

`glassmorphism acrylic desktop --domain style` 返回 Glassmorphism，`keyboard focus selection --domain ux` 返回 Focus States / Focus Not Obscured。只取适合浏览器扩展的局部玻璃效果和可见焦点，正常文字至少 4.5:1 的对比度。项目是原生 HTML/CSS/TypeScript；没有将 html-tailwind 或 WinUI 原生栈当作实际技术栈。
