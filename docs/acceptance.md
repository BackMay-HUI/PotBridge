## v0.3.1 — 弹窗尺寸修复

用户更新 v0.3.0 后报告：点击 Edge 工具栏图标只出现一根竖条。对比 v0.2 的可用尺寸规则，发现生产 UI 接入时把弹窗的 `max-width:none` 改成了 `max-width:100vw`，且内部容器跟随视口。工具栏弹窗由内容协商窗口尺寸，这会形成对初始窄视口的依赖。

用正式 popup.html 与生产控制器的 localhost 页面做实际浏览器检查，240px 视口下修复前 app / body / root 均为 240px，预期 560px 的回归检查失败。固定根文档、body 和 app 的尺寸后，同一视口下三者都为 560px，app 高 600px；五主题在 240px 和 560px 视口下均通过 560 × 600 检查，菜单切换与 Escape 焦点返回正常。临时视口覆盖已恢复。这是渲染器中的尺寸回归证据，不冒充 Edge 扩展窗口的实际结果。

v0.3.1 的 TypeScript / 生产构建、87 项扩展测试和 25 文件发行包校验通过。用户加载修复版后因目录变化而出现新的扩展 ID，重新运行安装脚本绑定后，明确反馈「已连接，完整显示，换肤与播放正常」。这是当前用户真实 Edge 与 PotPlayer 的复测确认，不是工具独立观察；不据此推断所有 DPI、屏幕、站点和编码均已验收。

尝试打开的公开样本为 [B 站普通视频](https://www.bilibili.com/video/BV1mpJB66EfV/)。浏览器工具未能可靠确认当前 Windows 浏览器地址，随后明确停止电脑操作；没有获得该样本的捕获、音画或拖动证据。扩展内部页面也不能由工具自动打开，重新加载扩展需要用户操作。没有将浏览器标签存在或 HTTP 请求成功计为播放通过。

升级期间用户已反馈可发现媒体，但随后确认是 `NATIVE_HOST_FORBIDDEN`，尚未进入播放验收。实际扩展 ID 已因新目录而改变；用户从 Windows 开始菜单打开 PowerShell，按当前 ID 重新安装后明确确认“安装成功，已连接”。本机连接成功不代表分轨音画与拖动已通过。

后续用户测试 [BV1cbnS6FEQD](https://www.bilibili.com/video/BV1cbnS6FEQD/) 的脱敏报告显示，分轨会话已建立，播放器发起 11 次请求，但音轨阶段返回 567、传输字节为 0。已按“预检有 Range、播放器可能不带 Range”的差异补齐 B 站点播中转：无范围请求补 `bytes=0-`；仅在上游确实返回完整零起点文件时对本地还原普通 200；显式拖动和不完整 206 保持原样，直播与通用媒体不变。对应回归测试先失败后通过。用户更新该修复的本机组件后，对同一视频明确确认“画面、声音、拖动均正常”。这是用户实际运行确认，不是工具独立观察，也不代表所有 B 站内容均可播放。

用户另确认在 [直播房间 33989](https://live.bilibili.com/33989) 选择的是 FLV 来源，播放正常，关闭网页上的插件弹窗后仍播放，结束中转后会暂停。该房间随后停播，记录不代表它持续在线。

DASH 官方参考页的首次反馈为 PotPlayer 提示服务器已关闭或地址错误。脱敏报告显示页面已发现 MPD，但它被较新的 MP4 候选排到列表末尾，实际发送的会话格式为 MP4。已用回归测试复现并统一清单在存储和展示中的优先级，避免默认发送后到的媒体片段。随后用户在 [DASH 官方参考页](https://reference.dashif.org/dash.js/latest/samples/dash-if-reference-player/index.html) 明确选择 DASH 来源，确认画面、声音和拖动正常。

无刷新导航的实际失败样本为 [BV1WRnV6vEBR 第一 P](https://www.bilibili.com/video/BV1WRnV6vEBR/)。自动化复现了预取播放信息被丢弃，以及新视频元数据和播放信息先后到达而初始全局状态滞后的两类缺口。适配器现缓存有界、未过期且身份可核对的来源，当前路由的 CID 确认后才转发。另有回归覆盖旧缺音轨缓存覆盖完整双轨的问题。用户使用修复包、按以下步骤复测后明确确认“来源、内容和音画均正常”。

复测时，重新加载扩展后须先刷新起始 B 站页面一次以载入新版脚本；随后点击切换视频或分 P，切换完成后不手动刷新再检测与发送。之前测试说明漏写起始页刷新，可能影响测试有效性，不能据此判定当时实际失败只有一个原因。本次导航修复仅涉及扩展，无需重装本机组件。

### 本机升级步骤

1. 结束现有中转，关闭 PotPlayer。将新版 `extension` 内容替换到原来加载的固定目录；在 Edge 的扩展管理页点击重新加载。改变目录时需重新核对扩展 ID。
2. 从 Windows 开始菜单打开 PowerShell，进入安装包目录，运行本机安装脚本；扩展和本机组件必须同时升级到协议 2。
3. 设置页重新检查连接，保留实际播放器路径。原有站点开关会保留，B 站若未开启，启用后刷新视频网页并开始播放。
4. 选择带“音视频分离”和音频编码的候选，先诊断，再发送；确认画面、声音、拖动和同步性。记录实际页面、画质、编码、播放器版本和完整错误文字。

协议不匹配会返回 `VERSION_MISMATCH`；缺少音轨会阻止发送。不要将孤立 m4s 请求或“已发送”状态视作完整播放成功。

## 支持边界

- DASH 同层多个 BaseURL、DRM/ContentProtection、外部 XML/xlink、MPD Patch、SubRepresentation 和部分扩展明确拒绝。常见十进制模板受支持，任意 printf 模板不受支持。
- 动态时长模板不猜测当前直播分片序号；预检成功仅代表已实际检查的清单和可解析初始化资源。SegmentBase 可检查索引范围，但不解析 SIDX 来证明首个媒体分片。
- 真实平台的长期解码、过期链接恢复和各种代理环境尚未全面验收；60 秒合成 HLS 测试仅证明传输及清理。
- 低延迟 HLS、SAMPLE-AES/DRM、WebRTC 和 WebSocket-FLV 仍不支持。可用画质和编码取决于网页已经返回的授权信息。

## v0.1 历史反馈

用户曾确认 v0.1 安装后显示“已连接”，原始视频成功播放。这是用户提供的实际运行结果，不是 v0.2 B 站或 DASH 验收。

安装期间曾遇到打包应用内 PowerShell 的 AppData 文件重定向，导致 Edge 报 `NATIVE_HOST_NOT_FOUND`。安装脚本已用文件句柄核对物理路径；用户从 Windows 开始菜单打开 PowerShell 安装后确认连接成功。此前中止的 900 秒测试不计为通过。
